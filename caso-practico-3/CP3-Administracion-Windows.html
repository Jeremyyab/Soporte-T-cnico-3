🏢 Escenario
DataTec S.A. — Configuración completa del SO Las dos estaciones virtuales están instaladas y en red. Ahora el área de TI debe configurar el sistema operativo: crear cuentas de usuario por departamento, establecer una carpeta de trabajo compartida entre ambas estaciones, habilitar el acceso remoto para soporte y ejecutar un diagnóstico completo del sistema.
⚠️ Prerequisito Las VMs del CP2 deben estar funcionando y comunicándose por ping antes de iniciar. Si algún grupo no completó el CP2, el docente proveerá una VM base para clonar.
✅ Nombre del grupo Usen el formato GrupoX para todos los archivos, usuarios y carpetas creados en este laboratorio.
🔧 Actividades del laboratorio 4 partes
1

Gestión de cuentas de usuario

Crear y configurar usuarios con distintos niveles de acceso en VM1.

1
Crear usuario estándar "SoporteTI-GrupoX"
Panel de Control → Cuentas de usuario → Administrar otra cuenta → Agregar nueva cuenta.
Tipo: Usuario estándar. Contraseña: Cenfotec2024!. Verificar que NO tiene derechos de administrador intentando instalar una app.
📸 Captura: Panel de cuentas mostrando el nuevo usuario y su tipo
2
Crear usuario administrador "AdminTI-GrupoX"
Mismos pasos. Tipo: Administrador. Contraseña: Admin.2024!.
Verificar diferencia: iniciar sesión como SoporteTI e intentar abrir lusrmgr.msc → debe pedir credenciales de admin.
3
Verificar usuarios desde CMD (como admin)
Abrir CMD como administrador y ejecutar:
net user ← lista todos los usuarios
net user SoporteTI-GrupoX ← detalle del usuario
net localgroup Administrators ← miembros del grupo admin
📸 Captura: salida del comando net user
2

Compartir carpeta entre VM1 y VM2

Crear carpeta compartida en red y verificar acceso bidireccional.

4
Crear y compartir carpeta en VM1
Crear carpeta: C:\Compartida-GrupoX
Clic derecho → Propiedades → Compartir → Uso compartido avanzado → Compartir esta carpeta.
Nombre del recurso: Compartida-GrupoX. Permisos: Todos → Lectura y escritura.
📸 Captura: ventana de compartir mostrando la ruta de red \\equipo\Compartida-GrupoX
5
Acceder a la carpeta desde VM2
Desde VM2, abrir Explorador de archivos → barra de dirección → escribir:
\\192.168.56.10\Compartida-GrupoX
Ingresar credenciales de admin de VM1 si se solicitan.
Crear archivo de texto: prueba-acceso-VM2.txt dentro de la carpeta compartida.
📸 Captura: archivo .txt creado desde VM2 visible en VM1
6
Mapear la carpeta como unidad de red en VM2
VM2 → Explorador → Este equipo → Conectar a unidad de red.
Letra: Z:. Carpeta: \\192.168.56.10\Compartida-GrupoX. Marcar: Conectar al iniciar sesión.
Verificar que la unidad Z: aparece en "Este equipo".
📸 Captura: unidad Z: visible en "Este equipo" de VM2
3

Habilitar y probar RDP entre VMs

Configurar Escritorio Remoto en VM1 y conectarse desde VM2.

7
Habilitar RDP en VM1
Abrir con sysdm.cpl → pestaña Acceso remoto → seleccionar "Permitir las conexiones de Escritorio remoto".
Verificar que el usuario AdminTI-GrupoX tiene permiso (Seleccionar usuarios → Agregar).
8
Verificar regla de firewall para RDP
Firewall de Windows → Permitir una aplicación → buscar "Escritorio remoto" → habilitarlo para redes privadas.
Verificar con CMD:
netstat -an | findstr 3389 ← debe aparecer LISTENING
📸 Captura: netstat mostrando puerto 3389 en estado LISTENING
9
Conectarse vía RDP desde VM2
Desde VM2: mstsc → Equipo: 192.168.56.10 → Conectar.
Usuario: AdminTI-GrupoX. Contraseña: Admin.2024!
Verificar que la sesión se establece y se puede controlar VM1 desde VM2.
📸 Captura obligatoria: sesión RDP activa mostrando el escritorio de VM1 dentro de VM2
4

Diagnóstico del sistema — Comandos CLI

Ejecutar comandos de diagnóstico y guardar los resultados.

10
Ejecutar diagnóstico completo de red desde VM1
Abrir CMD como Administrador y ejecutar en orden:
ipconfig /all > C:\diagnostico-red.txt
netstat -an >> C:\diagnostico-red.txt
ping 192.168.56.11 >> C:\diagnostico-red.txt
tracert 8.8.8.8 >> C:\diagnostico-red.txt
type C:\diagnostico-red.txt ← ver el contenido
📸 Captura: CMD mostrando contenido del archivo diagnostico-red.txt
11
Verificar integridad del sistema
En CMD como Administrador:
sfc /scannow ← puede tomar 5-10 minutos
systeminfo | findstr /C:"Nombre" /C:"Memoria" /C:"Sistema"
Anotar si sfc encontró y reparó archivos o no encontró problemas.
📸 Captura: resultado de sfc /scannow mostrando el estado
12
Revisar el Visor de Eventos
Abrir eventvwr.msc → Registros de Windows → Sistema.
Buscar errores (ícono rojo) o advertencias (ícono amarillo) recientes.
Anotar: Event ID, fuente y descripción del error más reciente encontrado.
📸 Captura: Visor de eventos con al menos un evento seleccionado y su detalle visible

  • Visor de eventos revisado y evento documentado

💬 Preguntas de discusión (retroalimentación)
Pregunta 1

¿Por qué es importante crear usuarios estándar en lugar de que todos sean administradores? ¿Qué riesgos de seguridad elimina esta práctica?

Pregunta 2

Al compartir la carpeta pusieron permiso "Todos" con lectura y escritura. En un entorno real con información sensible, ¿cambiarían esto? ¿Cómo lo harían de forma más segura?

Pregunta 3

El RDP usa el puerto TCP 3389. ¿Por qué es importante que el firewall solo permita ese puerto desde IPs conocidas y no desde internet abierto? ¿Qué ataque previene eso?

Pregunta 4

El comando sfc /scannow detecta archivos del sistema dañados. ¿En qué situación real del soporte técnico lo usarían? ¿Qué pasa si sfc no puede reparar el archivo?

Pregunta 5

En el Visor de Eventos encontraron un error. ¿Cómo usarían el Event ID para encontrar la solución? ¿Dónde buscarían información sobre ese ID específico?
