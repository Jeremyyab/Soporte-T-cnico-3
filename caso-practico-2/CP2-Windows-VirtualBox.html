🏢 Escenario
DataTec S.A. — Virtualización de estaciones de trabajo El equipo de TI de DataTec S.A. necesita preparar dos estaciones de trabajo virtualizadas para el área de soporte técnico. Antes de implementar en hardware físico, deben configurar y validar la conectividad entre las VMs usando VirtualBox. Su grupo actúa como el equipo de TI encargado.
⚠️ Requisitos del host antes de iniciar Verifiquen que el equipo tiene VirtualBox instalado, la ISO de Windows descargada, virtualización habilitada en BIOS (Intel VT-x o AMD-V) y al menos 8 GB de RAM disponibles.
✅ Nombre de las VMs Usen el formato: GrupoX-VM1 y GrupoX-VM2 donde X es su número de grupo asignado por el docente.

🔧 Actividades del laboratorio 3 partes
1

Crear e instalar VMs en VirtualBox

Configurar VM1 y VM2 con Windows e instalar el sistema operativo desde la ISO.

1
Crear VM1 en VirtualBox
Nueva → Nombre: GrupoX-VM1 · Tipo: Microsoft Windows · Versión: Windows 10/11 (64-bit). Asignar 2 CPU, 4 GB RAM. Crear disco VDI dinámico de 50 GB.
📸 Captura: Pantalla de resumen de la VM creada
2
Configurar red de VM1
Configuración → Red → Adaptador 1: Habilitado · Conectado a: Red solo-anfitrión (Host-Only) · vboxnet0. Adaptador 2: Habilitado · Conectado a: NAT.
3
Instalar Windows en VM1
Almacenamiento → Controlador IDE → Agregar ISO de Windows. Iniciar VM1 y seguir el asistente de instalación. Completar configuración inicial (región, usuario, contraseña).
4
Tomar Snapshot "SO-Limpio-VM1"
Con VM1 apagada o en pausa: Menú Máquina → Tomar instantánea. Nombre: SO-Limpio-VM1. Descripción: "Sistema operativo recién instalado sin configuraciones adicionales".
📸 Captura: Panel de Instantáneas con snapshot creado
5
Repetir pasos 1–4 para VM2
Crear VM2 con los mismos parámetros de hardware. Nombre: GrupoX-VM2. Instalar Windows. Snapshot: SO-Limpio-VM2.
2

Configurar IP estática y verificar conectividad

Asignar IPs fijas en ambas VMs y probar la comunicación entre ellas.

6
Verificar adaptadores de red en VM1
Iniciar VM1. Abrir CMD y ejecutar ipconfig /all para identificar los dos adaptadores. El adaptador Host-Only mostrará la red 169.254.x.x o sin IP (aún sin configurar).
7
Asignar IP estática en VM1 (adaptador Host-Only)
Panel de control → Redes e Internet → Centro de redes → Cambiar configuración del adaptador. Clic derecho en el adaptador Ethernet (Host-Only) → Propiedades → TCP/IPv4 → Usar la siguiente dirección IP:
IP: 192.168.56.10 · Máscara: 255.255.255.0 · Gateway: 192.168.56.1
📸 Captura: Propiedades TCP/IPv4 configuradas
8
Asignar IP estática en VM2 (adaptador Host-Only)
Igual que el paso anterior en VM2. IP: 192.168.56.11 · Máscara: 255.255.255.0 · Gateway: 192.168.56.1
9
Verificar configuración con ipconfig
En cada VM, abrir CMD y ejecutar:
ipconfig
Verificar que el adaptador Host-Only muestre la IP correcta (56.10 en VM1, 56.11 en VM2).
10
Ping entre VMs
En VM1, abrir CMD y ejecutar: ping 192.168.56.11
En VM2, abrir CMD y ejecutar: ping 192.168.56.10
Ambos deben responder con 4 paquetes enviados y recibidos.
📸 Captura: ping exitoso desde cada VM (obligatorio)
3

Diagnóstico — El ping no responde

Escenario de diagnóstico: identificar y resolver el bloqueo del ping.

Escenario Al ejecutar ping 192.168.56.11 desde VM1, el resultado es: "Request timed out" o "Destination host unreachable". Las IPs están bien configuradas y el adaptador Host-Only está activo. ¿Cuál es la causa más probable y cómo se soluciona?
11
Verificar qué está bloqueando el ping
El Firewall de Windows bloquea ICMP (ping) por defecto en redes nuevas. Para probarlo temporalmente:
Panel de control → Sistema y seguridad → Firewall de Windows → Desactivar firewall temporalmente.
Probar ping nuevamente. ¿Ahora responde?
12
Habilitar regla de ping en el Firewall (solución correcta)
No dejar el firewall desactivado. Crear regla específica:
Firewall de Windows → Configuración avanzada → Reglas de entrada → Habilitar:
"Compartir archivos e impresoras (Solicitud de eco - ICMPv4 de entrada)"
Repetir en VM2. Probar ping con el firewall activo.
📸 Captura: Regla de firewall habilitada + ping exitoso con firewall ON
13
Documentar hallazgos
Completar la tabla de diagnóstico con: síntoma observado, causa identificada, solución aplicada, resultado final. Adjuntar todas las capturas de pantalla al documento de entrega.
✅ Checklist de entrega
  • VM1 y VM2 creadas con los parámetros especificados
  • Windows instalado y funcional en ambas VMs
  • Snapshot "SO-Limpio" creado en cada VM
  • Adaptador Host-Only configurado en ambas VMs
  • IP estática asignada: 192.168.56.10 (VM1) y 192.168.56.11 (VM2)
  • Ping VM1 → VM2 exitoso (captura requerida)
  • Ping VM2 → VM1 exitoso (captura requerida)
  • Regla ICMP habilitada en firewall (no firewall desactivado)
  • Tabla de diagnóstico completada (Parte 3)
  • Documentación con todas las capturas de pantalla

💬 Preguntas de discusión (retroalimentación)
Pregunta 1

¿Por qué se configura la red en modo Host-Only y no Bridged para este laboratorio? ¿Qué pasaría si se usara NAT en ambos adaptadores?

Pregunta 2

¿Cuál es la diferencia entre un disco VDI dinámico y uno fijo? ¿En qué situación profesional usarían cada uno?

Pregunta 3

¿Por qué es importante tomar un snapshot antes de hacer cambios de configuración? ¿Qué riesgos elimina esta práctica?

Pregunta 4

El firewall bloqueó el ping. En un entorno real, ¿es correcto desactivar el firewall para solucionar este problema? ¿Cuál es la solución correcta?

Pregunta 5

¿Qué diferencia hay entre un Tipo 1 y un Tipo 2 de hipervisor? Si este laboratorio fuera en un datacenter real, ¿qué hipervisor usarían?
